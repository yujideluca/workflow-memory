# ADR-0002: One append-only event log folded by a pure function, instead of a protocol

- **Status:** accepted (reconstructed 2026-10-22 from `docs/DESIGN.md`)
- **Date:** 2026-10-19
- **Type (ISO/IEC/IEEE 14764):** perfective (replaced the old system)
- **Decided by:** Giovanni

## Context

The old workflow was a conversation between instances: numbered entries, "seen" cursors, owner folders, sync,
heartbeat, nightly review. It needed a machine alive and coordinating, and every new problem became a new rule. On
2026-10-18 a test-suite bug made the daily timer roll back and delete a day of work.

## Decision

One write primitive (create a file under `events/`) and one pure function (fold the log into views). Event files are
never edited or deleted; a change is a new event (`--supersedes`, `forget`). `views/` is generated by `mem build`
and never edited by hand. Standard library only.

## Alternatives considered

- **Keep the protocol and harden it** — every incident added rules; the coordination itself was the fragility.
- **A database or hosted service** — needs a server; GitHub plus files works from the app, the laptop and Actions.

## Consequences

Order of delivery never matters (test `test_order_independent_and_idempotent`). The invariants are enforced, not
just stated: hand-edited views fail `build --check` (`test_check_fails_when_a_view_was_edited_by_hand`), invalid or
secret-bearing events are quarantined (`test_privacy_boundary`), and the CI job `append-only` fails a push that edits
an existing event file in place. Claim-once is not atomic (see `docs/DESIGN.md`, Known limits).
