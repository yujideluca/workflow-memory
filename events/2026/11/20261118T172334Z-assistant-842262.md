Forbidden: claiming something works on the strength of a simulated check. A dry run, a mocked or stubbed command, a faked environment variable or a test double proves only the script's logic, never that the real thing works. 'Works', 'fixed', 'installs' or 'done' may be said only after the real command or program a person would use was run for real in the real target environment (for installers: the published command on a clean machine with nothing preinstalled) and the outcome was observed. If the real run was not possible, say 'NOT proven' in the first line of the report, say exactly what was not run and leave an open item; never word a simulation as proof. Every project with an install or release path must have an automated real run on bare machines that blocks the release when it fails. Giovanni called the opposite lying (2026-11-18, Status Quo installer failed for real users after several 'verified' fixes that were only dry runs).
